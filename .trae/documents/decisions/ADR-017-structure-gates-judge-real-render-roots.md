# ADR-017：结构门禁按真实渲染根判定，不再整文件扫描

- 状态：已采纳
- 日期：2026-11-26
- 仓：fewbie-starter
- 触发：round108 前端复用评审 R108-17（barrel 再导出误报）与 R108-03（页面门禁误报），以及 R108-01 把门禁接进宿主 CI

## 背景

两道结构门禁用整文件正则判定，规则本身正确，判定面却是错的：

| 门禁                      | 判定面                      | 后果                                                                                                                                                                                                   |
| ------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `check-page-contract.mjs` | 文件里第一个 `return <Tag>` | 路由文件常在页面之上定义 `AlertRow`、`KeyValueBlock` 这类子组件，它们的 `return <div>` 被当成页面根 —— 已经用 `PageShell` 的页面（alert-center、event-emitter、job-scheduler、projects 等 6 个）被报红 |
| `check-primitives.mjs`    | 所有 `export { ... }`       | barrel 的 `export { X } from "./x"` 被当成重复定义（nightwatch `analysis/blocks/index.tsx` 5 条全属此类）                                                                                              |

这两类误报的性质相同：**判定面（整个文件 / 所有导出语句）大于规则要守的对象（页面自身渲染的根 / 本地定义）**。把这样的门禁接进 CI（R108-01）会逼着作者为了迎合正则去挪动子组件，规则随即失去可信度——与 R108-17 记录的顺序要求一致：先修误报，再接门禁。

## 候选方案

| 方案                                    | 做法                                                                 | 结论                                                                       |
| --------------------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| A 为 6 个页面加豁免清单                 | 门禁内置白名单                                                       | **否决**：用户已明确拒绝豁免清单；白名单会让新页面复制同样的误报           |
| B 让页面把子组件挪到页面下方 / 另立文件 | 改动路由文件结构以迎合正则                                           | **否决**：把工具缺陷转嫁给业务代码，且子组件在上、页面在下是自然的阅读顺序 |
| C 收窄判定面                            | 页面门禁只看默认导出函数的 body；原语门禁跳过 `export { } from` 列表 | **采纳**：判定面与规则对象一致，宿主无需为门禁改变代码组织                 |

## 决策

1. **页面门禁**（`check-page-contract.mjs`）：
   - 用括号配对取出 `export default [async] function` 的 body；`export default Imported;`（薄再导出）直接放行。
   - body 内收集"页面自身"的 `return <Tag>`：函数体与箭头函数体是不透明边界，内层回调的返回不算页面根；`if` / `try` / `switch` 等控制流块透明，早返回仍然扫得到。
   - 每个页面根都必须是 `PageShell` / `PageHeader` 或大写组件标签；片段根只有在渲染 shell 时才放行。
   - 手写 `<h1>` 仍按整个文件扫描：路由文件里出现 `h1` 就意味着该路由绕过了 `PageHeader`，与它在哪个组件里无关。
2. **原语门禁**（`check-primitives.mjs`）：`export { X } from "..."` 的再导出不计入组件名；重复定义在真正的声明处报。
3. 两道门禁的自测（`scripts/gates.test.mjs`）覆盖：helper 在上 / 页面在下的合规样例、带花括号的早返回、body 内回调返回原始元素不误报、barrel 再导出不误报而真重复仍报红。

## Cross-host check

| 维度     | 框架层（fewbie-starter）            | 宿主层（nw / cb / 未来宿主）          |
| -------- | ----------------------------------- | ------------------------------------- |
| 门禁脚本 | `scripts/` 由本 ADR 修改            | 由 `template update` 同步，宿主不手改 |
| 页面写法 | 页面可以自由把子组件放在页面上方    | 无需为门禁调整文件结构                |
| 判定范围 | 与规则对象一致（页面根 / 本地声明） | 同左                                  |
| 回滚     | 恢复整文件扫描                      | 同左，无需宿主改动                    |

## 验证

- `node --test --import tsx scripts/gates.test.mjs`：18 项全绿（含 3 项新增负/阳性对照）。
- nightwatch-frontend 上运行修正后的页面门禁：报红集合从"6 个已合规页面 + 缺 5 个真实违规"变为 28 个真实违规文件，由 R108-03 逐个修复。
- `check-primitives.mjs` 在 nightwatch 上不再报告 `components/analysis/blocks/index.tsx`，手工制造的真重复仍报红。

## 更新记录

- 2026-11-26：body 起点改为「参数列表的 `)` 之后」，`function Page({ params }: Props)` 的解构参数不再被误当作函数体；自测新增 1 例解构参数。该修正属实现细节，不改变本 ADR 的判定规则（R108-03 落地时发现）。
